NAME

SAPHanaTopology - 2つのSAP HANAデータベースをシステムレプリケーションで管理するのに役立ちます。

SYNOPSIS

SAPHanaTopology [start | stop | status | monitor | meta-data | validate-all | reload | methods | usage ]

DESCRIPTION

SAPHanaTopologyはリソースエージェント（RA）であり、SAP HANAのトポロジーを分析し、クラスタ情報ベース（CIB）属性を介してクラスタ内のすべてのノードにすべての調査結果を「送信」します。これらの属性はSAPHanaController RAによって取得され、SAP HANAデータベースを制御します。さらに、SAPHanaTopology はローカルの saphostagent を起動して監視します。

リソースエージェントは、SAPが提供する以下のインタフェースを使用します：

1. landscapeHostConfiguration.py
landscapeHostConfiguration.pyには、HANAシステムのステータスとノードの役割に関する詳細な出力があります。私たちのモニターでは、全体的なステータスが重要です。この全体的なステータスはスクリプトのリターンコードで報告されます： 0: Internal Fatal, 1: ERROR, 2: WARNING, 3: INFO (ホストの自動フェイルオーバーが発生したなど), 4: OK
SAPHanaTopology リソースエージェントは、リターンコード 0 を FATAL、1 を NOT-RUNNING（または ERROR）、リターンコード 2+3+4 を RUNNING と解釈します。FATAL は、ステータスを判断できないことを意味します。
SAPHanaTopologyはlandscapeHostConfiguration.pyの出力をスキャンしてクラスタノードのロールを特定します。ロールとは、ネームサーバとインデックスサーバの設定済みおよび現在のロールを意味します。

2. hdbnsutil
インターフェイスhdbnsutilは、システムレプリケーションの「トポロジー」とSAP HANAデータベースの現在の構成（プライマリ/セカンダリ）を確認するために使用されます。インターフェイスの2番目のタスクは、システムレプリケーションのテイクオーバー（sr_takeover）を実行したり、以前のプライマリを新しいプライマリに登録（sr_register）したりすることです。スケールアウト設定では、hdbnsutil に時間がかかることがあります。SAPHanaTopology はタスク1のみを使用します。SAPHanaController は 3 つのタスクすべてを使用しています。

3. saphostctrl
インターフェース saphostctrl は、関数 ListInstances を使用して SAP HANA インスタンスの仮想ホスト名を特定します。これは通常、HANAのインストール時に使用されたホスト名です。

ノード・ステータス属性を介して調査結果を「送信」する方法は、次のバージョンで変更される可能性があります。そのため、これらの属性を「API」と考えないでください。また、自動的に設定されるノード属性は、通常の操作では手動で調整しないでください。属性の名前やセマンティクスは次のバージョンで変更される可能性があります。

Please see also the REQUIREMENTS section below.

SUPPORTED PARAMETERS

This resource agent supports the following parameters:

SID

SAP System Identifier. Has to be same on both instances. Example "SID=SLE".

InstanceNumber

SAP HANAデータベースの番号。システムレプリケーションでは、インスタンス番号+1 もブロックされます。例 "InstanceNumber=00".

HANA_CALL_TIMEOUT

情報を受け取るためにHANAを呼び出す際のタイムアウト時間を定義します。これは例えばlandscapeHostConfiguration.pyのようになります。独自のタイムアウト値を持つHANAへの特定の呼び出しがいくつかあります。例えば、sr_takeoverコマンドはタイムアウトしません(inf)。タイムアウトに達した場合、リターンコードは124になります。HANAコールのタイムアウトを増やす場合は、Linuxクラスタリソースの操作タイムアウトも調整する必要があります。
Optional. Default value: 120

SUPPORTED PROPERTIES

hana_${sid}_glob_filter

Global cluster property hana_${sid}_glob_filter . このプロパティは、どのメッセージが RA によってログに記録されるかを定義する。サポート・エンジニアから要求された場合のみ設定する。通常の操作では、デフォルトで十分です。
Message Types: [ act | dbg | dec | flow | top ]
ACT: Action. Start, stop, sr_takeover and others. See also section SUPPORTED ACTIONS.
DBG: Debugging info. Usually not needed at customer site. See SUSE TID 7022678 for maximum RA tracing.
DEC: Decision taken by the RA.
FLOW: Function calls and the respective return codes.
TOP: Topology. Messages related to HANA SR topology, like site name and remote site.
Optional, advanced. Default value: ra-act-dec-lpa.

SUPPORTED ACTIONS


This resource agent supports the following actions (operations):

start

クローンのステータスを 「started 」に設定する。

stop

クローンのステータスを 「stopped 」に設定する。

status

HANAインスタンスが実行中かどうかを報告します。推奨される最小タイムアウト： 60.

monitor

ノードHANAの役割とランドスケープのステータスを分析します。推奨される最小タイムアウト： 600. 推奨間隔 50.

validate-all

パラメータが有効かどうかを報告する。推奨される最小タイムアウト： 5.

meta-data

リソースエージェントのメタデータを取得します。推奨される最小タイムアウト： 5.

methods

リソースエージェントがサポートするメソッド(操作)を報告します。推奨される最小タイムアウト： 5.

reload

リソースのリカバリーを強制せずにパラメータを変更する。推奨される最小タイムアウト： 5.

RETURN CODES

リターンコードはOCFクラスターフレームワークによって定義されている。OCFの定義は後述のウェブサイトを参照されたい。
また、HANA_CALL_TIMEOUTを超過した場合は、リターンコード124が使用されます。

EXAMPLES

* HANA スケールアップのための SAPHanaTopology リソースの構成例。
また、これを実行するには SAPHanaController リソースが必要です。SAPHanaTopology の監視インターバルは、その SAPHanaController のインターバルよりも短くする必要があります。

primitive rsc_SAPHanaTop_SLE_HDB00 ocf:suse:SAPHanaTopology \
op start interval="0" timeout="600" \
op stop interval="0" timeout="600" \
op monitor interval="50" timeout="600" \
params SID="SLE" InstanceNumber="00"

clone cln_SAPHanaTop_SLE_HDB00 rsc_SAPHanaTop_SLE_HDB00 \
meta clone-node-max="1" interleave="true"

* HANA スケールアウトのための SAPHanaTopology リソースの構成例。
HANAは、それぞれ5つのノードを持つ2つのサイトで構成されている。追加のクラスタノードは、スプリットブレイン状況の多数決メーカーとして使用される。さらに、これを実行するには SAPHanaController リソースが必要です。SAPHanaTopology の監視インターバルは、その SAPHanaController のインターバルよりも短くする必要があります。

primitive rsc_SAPHanaTop_SLE_HDB00 ocf:suse:SAPHanaTopology \
op start interval="0" timeout="600" \
op stop interval="0" timeout="600" \
op monitor interval="50" timeout="600" \
params SID="SLE" InstanceNumber="00"

clone cln_SAPHanaTop_SLE_HDB00 rsc_SAPHanaTop_SLE_HDB00 \
meta clone-node-max="1" interleave="true"

location SAPHanaTop_not_on_majority_maker cln_SAPHanaTop_SLE_HDB00 -inf: vm-majority

order SAPHanaTop_first Optional: cln_SAPHanaTop_SLE_HDB00 mst_SAPHanaCon_SLE_HDB00

* プリミティブは "rsc_SAPHanaTop_SLE_HDB00" で、クローンは "cln_SAPHanaTop_SLE_HDB00" です。制約の名前は "SAPHanaTop "で始まります。

# crm configure show | grep SAPHanaTop
# crm configure show rsc_SAPHanaTop_SLE_HDB00
# crm configure show cln_SAPHanaTop_SLE_HDB00
# crm configure show SAPHanaTop_first

* SAPHanaTopology syslogエントリとHANAネームサーバートレースエントリの関連付け。

# grep "SAPHanaTop.*16933.*monitor_clone" /var/log/messages | awk '{print $1,$3,$7,$11,$12,$13}'
# su - hxeadm
~> cdtrace
~> grep "2023-11-01.*parent.*16933" nameserver_*trc | awk '{print $2,$3,$22,$23,$24,$25}'
~> exit
